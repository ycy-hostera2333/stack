## 一、会让回测结果失真的问题

### 1. 开盘涨停漏判（偏乐观）

`engine.py` / `paper.py` 用 `开盘价 >= 前收 × 1.1 − 1e-6` 判断一字涨停。
交易所的涨停价是四舍五入到分的：前收 10.13 的涨停价是 11.14，不是 11.143。
凡是向下取整的涨停（约一半）都判不出来，回测照样在一字板上「买到」。
引擎还把价格存成 float32，123 元附近精度只有 1e-5，比容差还粗。

自检「模拟盘与引擎逐笔等价」在合成数据上抓到了它：引擎在 002480 的一字涨停日
买进了，模拟盘（直接读库，float64）没买。

修正：`config.hit_limit_up / hit_limit_down`，容差一分钱（低价股不超过前收的 0.5%），
引擎、模拟盘、因子的可交易判定三处统一；引擎面板改用 float64。

### 2. 开仓资金用了当日收盘价（前视）

每仓预算 = (现金 + 持仓市值) / 仓位数，持仓市值按**当日收盘价**算，而成交在开盘。
改为按当日开盘价估值。停牌持仓原来不计入总资产（预算偏小），现在按最后收盘价计入。

### 3. 停牌持仓按成本价计价

涨了 50% 的票一停牌，净值当天回吐全部浮盈，复牌再跳回来。回撤、波动率、夏普都被扭曲。
改为按停牌前最后收盘价计。新增自检「停牌期间持仓按停牌前收盘价计价」。

### 4. 绩效指标漏掉首日

- 最大回撤和日收益序列从净值表第一行起算，首日就亏的那部分不算回撤；
  现在把初始资金接在最前面。模拟盘的最大回撤同口径。
- 基准从 dates[1] 起算、策略从 dates[0] 收盘的初始资金起算，基准漏掉一天；
  现在两边同一起点。

### 5. 每日信号的多因子排名口径与回测不一致

打分型策略（growth_value）在信号页只在「满足买入条件的股票」里排百分位，
引擎和模拟盘在「全部有效股票」里排。总体不同，加权和的先后就可能变，
信号页的前几名和回测/模拟盘同一天会买的不是同一批。改为全部股票。

### 6. 参数可调、但大多数取值会让策略静默不出信号

ma_trend / rsi_reversal / momentum_rotation 把周期拼进列名（`df[f"ma{n}"]`），
而通用指标只备了 5/10/20/60/120。界面上把均线调到 30，entry() 就 KeyError，
被引擎吞掉，表现为「一个信号都没有」。新增 `indicators.add_periods()`，要哪个周期现算。
ma_trend 加了「快线 < 中线 < 慢线」的参数校验。

### 7. 调了也没用的参数

- momentum_rotation 的「买入排名分位 / 卖出排名分位」：entry/exit 一行都没用到。
- growth_value 的 `min_amount`：没有任何代码读过它。

从界面下线。为了不让老模拟盘账户（参数随账户落库）加载失败，新增
`Strategy.retired`：这些参数名传进来时静默丢掉。

### 8. Tushare 源把涨跌幅整列清空

`tushare_source.fetch_daily_qfq` 已经给了 pct_chg，`source._fetch_tushare` 随后
`df["pct_chg"] = pd.NA`。Tushare 主要补退市股，于是退市股的涨跌幅全是 NULL，
defensive 的「近 20 日最大单日涨幅」永远选不中它们——幸存者偏差从后门回来了。

## 二、可靠性

- **模拟盘单日推进改为一个事务**。原来卖出、记成交、删持仓各自提交，现金和
  last_date 最后才写；中途抛异常，卖出所得就凭空消失。前向记录不可再生。
- **建账户回补 vs 守护线程**：回补期间守护线程醒来会对新账户 catch_up，
  直接把 last_date 推到最新，回补剩下的日子被静默跳过。现在两者互斥。
- **同步重入**：「是否在同步」的检查和置位不是原子的，连点两下（或守护线程同时
  决定同步）会并发两轮。改为加锁抢占。
- API：回测起始日早于库内数据、跟踪止损配不算 ATR 的策略，原来返回 500，
  现在返回 400 和原本就写好的那句说明。
- 网页模拟盘页加载失败时引用了未定义变量，错误信息出不来。

## 三、速度

合成库（约为真实库 1/3 大小）上的实测，结果与改前逐位一致：

| 场景 | 改前 | 改后 |
|---|---|---|
| 网页上改参数重跑回测（686 只，2019-2026） | ~6 s | ~3 s |
| 每日信号 regime_momentum | 4.6 s | 2.6 s |
| 模拟盘逐日推进（400 只） | 3.7 s/天 | 2.25 s/天 |

做法：

- `store.load_daily` / `trading_days` / `last_complete_day` 按 `PRAGMA data_version`
  缓存。任何连接（包括别的进程）提交写入后版本号就变，缓存随即失效。
  同一份全市场行情第二次读从 7.8 s 降到 0.6 s。
- 各内置策略声明只算自己用到的通用指标（`Strategy.indicators`），
  自检逐只比对精简集与全量下的 entry/exit/score/reason 完全一致。
  比对时抓到 ma_trend 等三个策略漏了基类默认打分要的 mom60；基类的默认打分
  也改成缺列时现算，不再静默返回 0。
- `store.iter_stocks()`：五处重复的「按股票分组 + 排序 + 截负价」合成一个，
  按代码边界切片，省掉 groupby 和逐只排序。
- regime_momentum / growth_value 的新增列一次拼接；regime_momentum 的入场判断走 numpy。
- 引擎的日期映射用二分查找代替逐只 strftime + 字典查找。

试过、没采用：把 daily 表改成 WITHOUT ROWID。合成库上没有稳定收益，
而迁移用户 1GB 的真实库有风险。

## 四、结构与界面

- `source.fetch_daily` 四段复制粘贴的「试一个源」合成一个循环；
  没配 token 时失败原因写「未配置 token」，不再是「空应答」，也不计入熔断。
- `start_stack.ps1` 去掉写死的个人路径（改用脚本所在目录），加依赖安装。
  保持纯 ASCII：Windows PowerShell 5.1 按 GBK 读无 BOM 文件，中文会乱码。
- 回测页、新建模拟盘账户加「到期续持」开关（引擎早就支持，界面没有入口）。
- 策略说明默认只显示第一行，可展开（growth_value 的说明有两千多字）。
